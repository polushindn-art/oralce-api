# Распределение задач между программистами

## Роли и технологии

| Роль | Технологии | Ответственность |
|------|------------|------------------|
| **Программист 1 (Бэкенд + Android)** | Spring Boot, Kotlin/Java, Android, Room, WebSocket, OkHttp | REST API (оркестратор), ТСД-клиент, Room, синхронизация, интеграция с Oracle |
| **Программист 2 (Интеграция 1С)** | 1С:Предприятие 8.3, HTTP, WebSocket (клиент), SQL (Oracle для чтения) | Всё, что связано с 1С: очередь `WMS_TO_1C`, обработка документов, WebSocket-клиент 1С к REST API |
| **Программист 3 (Openfire + XMPP)** | Openfire, Smack (Android), XMPP, Foreground Service, WakeLock, FCM | Настройка Openfire, XMPP-клиент на ТСД, push-уведомления, пробуждение устройства, чат |

---

## Программист 1 — Бэкенд + Android (ядро системы)

### Что делает

**REST API (Spring Boot):**
- Эндпоинты `/v1/wms/receive`, `/v1/wms/complete`, `/v1/sync/pull`
- WebSocket-сервер для активной работы ТСД (WSS, порт 443)
- Интеграция с Oracle через JDBC + JSON-колонки
- Интеграция с Openfire (отправка XMPP-сообщений через бота)
- Health check (`/actuator/health`), метрики

**Android-приложение (клиентская часть, кроме XMPP):**
- Room (локальное хранилище, Single Source of Truth)
- WorkManager (фоновая синхронизация)
- WebSocketManager (активная работа)
- Repository + ViewModel + UI (CameraX / сканер)
- Offline-first логика
- Логирование переходов состояний ТСД

**Скрипты Oracle:**
- Создание таблиц `WMSHEAD`, `WMSSPEC`, `MARK`, `MARKLINK`
- Партиционирование (ежемесячное)
- Индексы (локальные)
- Триггер защиты завершённых документов

**Документация:**
- OpenAPI/Swagger
- Схема БД (ER-диаграмма)
- Инструкция по развёртыванию (docker-compose)

### Не делает

- Не настраивает Openfire
- Не реализует XMPP-клиент на ТСД
- Не пишет код 1С

### Интеграционные точки

| С кем | Что передаёт | Как |
|-------|--------------|-----|
| Программист 2 | Завершённые документы | Через таблицу `WMS_TO_1C` в Oracle |
| Программист 3 | Команды на push-уведомления | XMPP (через бот-пользователя Openfire) |

## Программист 2 — Интеграция 1С

### Что делает

**На стороне 1С:**
- WebSocket-клиент (подключение к REST API, порт 443 WSS) для получения уведомлений о новых документах
- HTTP-клиент для чтения очереди `WMS_TO_1C` (или прямого доступа к Oracle через внешний источник данных)
- Обработку документов: приёмка, перемещение, списание → создание документов 1С (Приходный ордер и т.п.)
- Периодический опрос очереди (раз в 1–5 минут) — fallback-механизм
- Обновление `WMS_TO_1C` (статус `PROCESSED` / `FAILED`, поле `onec_doc_number`)
- Логирование ошибок обработки

**Интеграция с Oracle (только чтение):**
- Возможность читать `WMSHEAD`, `WMSSPEC`, `MARKLINK` через ODBC / внешний источник
- Забирать документ по `wmshead_rn`

**Прочее:**
- Обеспечение идемпотентности (проверка, что документ уже обработан)
- Инструкция для администратора 1С по настройке подключений (WebSocket, HTTP)

### Не делает

- Не реализует REST API оркестратор
- Не пишет Android-код
- Не настраивает Openfire

### Интеграционные точки

| С кем | Что получает | Как |
|-------|--------------|-----|
| Программист 1 | Уведомление о новом документе | WebSocket от REST API |
| Программист 1 | Данные документа | Чтение `WMSHEAD` / `WMSSPEC` из Oracle |

## Программист 3 — Openfire + XMPP (коммуникации и пробуждение ТСД)

### Что делает

**Настройка Openfire:**
- Установка и конфигурация (порт 5222, офлайн-очередь)
- Создание бот-пользователя для отправки сообщений от REST API
- Настройка FCM / Push-уведомлений (если используется)
- Поддержка статусов доставки/прочтения

**Android-клиент (только XMPP-часть):**
- XMPPClient на Smack (подключение к Openfire, порт 5222)
- Foreground Service с уведомлением в статус-баре
- WakeLock + WifiLock (удержание соединения)
- BroadcastReceiver для автозапуска после перезагрузки (`BOOT_COMPLETED`)
- **Разработка тестового приложения WakeUp Test согласно отдельному ТЗ**
- **Инструкция для оператора: как отключить оптимизацию батареи**
- **Протокол тестирования энергопотребления (15 часов ночью)**

**Интеграция с REST API:**
- Предоставляет программисту 1 `XMPPService.sendMessage(to, body)` (или реализует эндпоинт `/v1/notification/send`)

**Тестирование:**
- Задержка push-уведомления < 10 секунд
- Офлайн-очередь: сообщение доставляется при возвращении ТСД в сеть

### Не делает

- Не пишет бэкенд Spring Boot
- Не интегрируется с Oracle
- Не занимается 1С

### Интеграционные точки

| С кем | Что передаёт | Как |
|-------|--------------|-----|
| Программист 1 | Интерфейс для отправки XMPP-команд | Smack-библиотека или REST-прокси |
| Программист 1 (Android) | XMPP-сервис в общем Android-проекте | `LiveData` / `Flow` |

## Совместная работа

| Задача | Кто делает | Кто проверяет |
|--------|------------|----------------|
| Схема передачи документа из Oracle → 1С | Программист 2 | Программист 1 (корректность очереди `WMS_TO_1C`) |
| WebSocket-уведомления от REST API к 1С | Программист 1 (серверная часть) | Программист 2 (подключается как клиент) |
| XMPP-отправка из REST API | Программист 3 (даёт библиотеку или REST-прокси) | Программист 1 (вызывает) |
| Общий Android-проект | Программист 1 (ядро) + Программист 3 (XMPP) | Ежедневная синхронизация по интерфейсам |
