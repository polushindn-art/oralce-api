# 📘 Руководство по написанию KDoc-документации (Oracle API)

В проекте настроена автоматическая генерация документации по исходному коду с помощью **Dokka (KDoc)**. Сгенерированный сайт доступен по адресу `/docs/index.html` и запекается в сборку или обновляется через скрипт `make_docs.cmd`.

Этот документ описывает стандарты и правила документирования кода на Kotlin в нашем проекте.

---

## 1. Основные правила синтаксиса
* **Блок комментария:** Всегда используйте многострочный комментарий, начинающийся с двух звездочек: `/** ... */`.
* **Краткое описание:** Первое предложение должно быть емким резюме — оно отображается в общих списках пакетов и классов.
* **Внутренние ссылки:** Чтобы сослаться на другой класс, метод или свойство проекта, используйте квадратные скобки: `[MyApiResponse]` или `[PictureController.upload]`. Dokka автоматически превратит их в кликабельные ссылки.

---

## 2. Основные теги
* `@param имя_параметра` — описание аргумента функции или конструктора.
* `@return` — описание того, что возвращает метод (не указывается для функций с типом `Unit`).
* `@throws ИмяИсключения` — описание ситуации, в которой выбрасывается исключение.

---

### 📦 2. Объекты передачи данных (`DTO` / `data class`)
Документируйте поля, особенно если они содержат специфичные бизнес-статусы или коды.

```kotlin
/**
 * DTO для передачи информации о телефонном номере контрагента.
 */
data class AgnPhoneNumberDto(
    /** Уникальный внутренний идентификатор записи в БД */
    val id: Long,
    
    /** Номер телефона в международном формате или внутренний добавочный */
    val phoneNumber: String,
    
    /** Признак основного номера для связи (true — основной) */
    val isPrimary: Boolean
)
```

## 4. Как обновить документацию в проекте?

1. Пишите код и добавляйте KDoc-комментарии `/** ... */` по мере разработки.
2. Для быстрой локальной генерации и обновления сайта документации запустите скрипт в корне проекта:
   ```cmd
   make_docs.cmd
   ```
3. Скрипт автоматически запустит генератор документации и обновит файлы в папке `src/main/resources/static/docs`.
4. Проверьте результат, открыв в браузере `http://localhost:8080/docs/index.html`.
