# 🐳 Docker для разработчика: основы и команды

Docker — это инструмент для упаковки приложений и их окружения в стандартизированные пакеты (контейнеры). Это гарантирует, что код будет работать одинаково на любом компьютере или сервере.

---

## 1. Как устроен Docker (Принципы работы)

* **Контейнер vs Виртуальная машина (VM):** Виртуалка эмулирует железо и ОС целиком (тяжелая и медленная). Контейнер делит ядро операционной системы хоста, весит мало и запускается за доли секунды.
* **Основные сущности:**
    1. **Образ (Image):** Неизменяемый шаблон (чертеж), содержащий приложение, среду выполнения (например, JDK) и зависимости.
    2. **Контейнер (Container):** Запущенный экземпляр образа. Можно запустить сколько угодно контейнеров из одного образа.
    3. **Dockerfile:** Текстовый файл с инструкциями для сборки образа.
    4. **Реестр (Registry):** Хранилище образов (например, Docker Hub или локальный реестр).

## 2. Шпаргалка по базовым командам Docker

### 📦 Работа с образами
* Посмотреть список локальных образов: `docker images`
* Удалить локальный образ: `docker rmi id_образа`

### 🚀 Запуск и управление контейнерами
* Запустить контейнер в фоне:
  `docker run -d -p 8080:8080 --name my_container имя_образа`
  *(Флаги: `-d` — фон, `-p` — проброс портов `хост:контейнер`, `--name` — имя)*
* Посмотреть активные контейнеры: `docker ps`
* Посмотреть все контейнеры (включая остановленные): `docker ps -a`
* Остановить контейнер: `docker stop имя_или_id`
* Перезапустить контейнер: `docker restart имя_или_id`
* Удалить контейнер: `docker rm имя_или_id`

### 🔍 Диагностика
* Просмотр логов в реальном времени: `docker logs -f имя_или_id`
* Мониторинг ресурсов (CPU, память): `docker stats`
* Зайти внутрь работающего контейнера: `docker exec -it имя_или_id sh`

## 3. Docker Compose (Управление множеством контейнеров)

Когда проект состоит из нескольких сервисов (например, Spring Boot приложение + база данных + мониторинг), запускать каждый контейнер вручную неудобно. Для этого используется **Docker Compose**.

Все сервисы описываются в одном файле **`docker-compose.yml`**:

```yaml
version: '3.8'

services:
  app:
    image: oracle-rest-api.ars:5001/oracle-api:latest
    container_name: oracle-prod
    ports:
      - "8080:8080"
    environment:
      - SPRING_PROFILES_ACTIVE=prod
      - DB_URL=jdbc:oracle:thin:@db:1521:XE
    restart: always
    networks:
      - app-net

networks:
  app-net:
    driver: bridge
```

### Основные команды Docker Compose:
* **Запустить все сервисы в фоне (из папки с docker-compose.yml):**
  ```bash
  docker compose up -d
  ```
* **Остановить и удалить контейнеры:**
  ```bash
  docker compose down
  ```
* **Посмотреть логи всех сервисов:**
  ```bash
  docker compose logs -f
  ```
* **Пересобрать и перезапустить контейнеры (после изменения кода/конфига):**
  ```bash
  docker compose up -d --build
  ```

## 4. Тома (Volumes) — Сохранение данных
По умолчанию все файлы, созданные внутри контейнера (например, загруженные картинки, базы данных или файлы отчетов), **удалятся**, когда контейнер будет уничтожен или обновлен.

Чтобы данные жили вечно, используют **Volumes (тома)**, привязывая папку на хосте к папке внутри контейнера:
```bash
docker run -d -v /path/on/host:/app/uploads my_image
```
В `docker-compose.yml` это записывается так:
```yaml
volumes:
  - ./uploads:/app/uploads
```

## 5. Переменные окружения (Environment Variables)
Чтобы не хардкодить пароли, порты и настройки в коде Spring Boot, их передают через переменные окружения:
* Через флаг командной строки:
  `docker run -e SPRING_PROFILES_ACTIVE=prod -e DB_PASSWORD=secret my_image`
* Либо через файл `.env`, лежащий рядом с `docker-compose.yml`:
  ```env
  SPRING_PROFILES_ACTIVE=prod
  SERVER_PORT=8080
  ```
  Использование в конфиге Compose: `environment: - SPRING_PROFILES_ACTIVE=${SPRING_PROFILES_ACTIVE}`

## 6. Очистка системы (Если закончилось место)
Контейнеры со временем оставляют неиспользуемые слои и кэш. Полная очистка системы выполняется одной командой:
```bash
docker system prune -a --volumes
```
*(Внимание: удалит все остановленные контейнеры, неиспользуемые сети и образы, которые не используются ни одним запущенным контейнером).*
