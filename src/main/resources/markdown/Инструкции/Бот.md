# 📖 Техническая документация: Архитектура и принципы работы бота

## 1. Общая архитектура
Бот представляет собой Spring Boot приложение, которое взаимодействует с API мессенджера (MAX API) через механизм **Long Polling**, работает с реляционной базой данных Oracle (через Spring Data JPA) и интегрирован с внутренними корпоративными сервисами (телефония Asterisk, складские остатки, справочник сотрудников).

### Основной стек технологий:
* **Язык:** Kotlin
* **Фреймворк:** Spring Boot (Web, JPA, Scheduling)
* **База данных:** Oracle Database (`QREAL` schema)
* **Многопоточность:** Kotlin Coroutines (`Dispatchers.IO`) для асинхронной обработки входящих событий
* **HTTP-клиенты:** RestTemplate (для API бота) и OkHttp (для мультипарт-загрузки файлов, фото и сканирования штрихкодов)

## 2. Структура базы данных (`MAX_USER_AGN`)
Таблица служит связующим звеном между пользователями мессенджера и контрагентами/сотрудниками компании.

| Поле             | Тип         | Описание                                                                 |
|:-----------------|:------------|:-------------------------------------------------------------------------|
| `RN`             | NUMBER (PK) | Уникальный идентификатор записи                                          |
| `USER_ID`        | VARCHAR2    | ID пользователя в системе мессенджера                                    |
| `CHAT_ID`        | VARCHAR2    | ID чата для отправки уведомлений                                         |
| `USER_NAME`      | VARCHAR2    | Имя пользователя                                                         |
| `PHONE`          | VARCHAR2    | Номер телефона (очищенный)                                               |
| `PHONE_TAIL`     | VARCHAR2    | Последние цифры телефона (вычисляется автоматически для быстрого поиска) |
| `BOT_TYPE`       | VARCHAR2    | Тип бота (`MAIN`, `AUTH`, `SUPPORT`)                                     |
| `IS_ACTIVE`      | NUMBER(1)   | Статус активности (`1` — активен, `0` — удален/отписался)                |
| `NOTIF_CALLS`    | NUMBER(1)   | Настройка: уведомления о звонках (`1` — вкл, `0` — выкл)                 |
| `NOTIF_BIRTHDAY` | NUMBER(1)   | Настройка: уведомления о ДР (`1` — вкл, `0` — выкл)                      |
| `AVATAR`         | BLOB        | Аватар пользователя (опционально)                                        |

## 3. Основные модули и сервисы

### 3.1. Ядро Polling-сервиса (`MaxMainPollingService`)
Отвечает за непрерывный опрос сервера (`/updates`) с использованием маркера (`marker`).
* **Обработка событий (`processUpdate`):**
    * `bot_started` — пользователь запустил бот, сохраняется аватар, активируется запись, выводится приветствие/меню.
    * `bot_stopped` — пользователь заблокировал бот, запись деактивируется (`is_active = 0`).
    * `message_created` — обработка входящих текстовых сообщений, фотографий (сканирование штрихкодов через `BarcodeService`) или переданных контактов (VCF / кнопка «Поделиться номером»).
    * `message_callback` — обработка нажатий на инлайн-кнопки (меню, поиск, настройки, отписка). Защищена от двойных кликов (`processedCallbacks` с TTL 10 секунд).

### 3.2. Клиентский слой API (`MaxBotMainClientService` & `MainBotMessageService`)
* Инкапсулирует всю работу с REST API мессенджера.
* Умеет отправлять текстовые сообщения, сообщения с инлайн-клавиатурами (`sendMessageWithInlineKeyboard`).
* Реализует сложный механизм загрузки изображений (например, QR-кодов дисконтных карт): получает временный URL для загрузки (`/uploads`), загружает бинарные данные через OkHttp в формате `multipart/form-data`, парсит сложный JSON-ответ со структурой `photos -> id -> token` и отправляет фото с подписью и кнопками.

### 3.3. Регистрация и проверка статуса (Клиент / Сотрудник)
* При первом входе пользователь видит кнопку **«📝 Регистрация»**.
* При нажатии бот просит поделиться номером телефона.
* По номеру телефона система определяет, является ли пользователь сотрудником (сравнивая `PHONE_TAIL` с корпоративным `phonebookRepository`).
* В зависимости от роли формируется динамическое меню:
    * **Клиентам** доступны: Мои данные, Поиск товара, Моя дисконтная карта, Помощь.
    * **Сотрудникам** дополнительно открываются: Поиск сотрудников, Настройки уведомлений.

### 3.4. Система персональных настроек (`Settings`)
Сотрудники могут гибко управлять своими уведомлениями через меню **«⚙️ Настройки»**:
* **Звонки (`NOTIF_CALLS`):** Вкл/Выкл уведомления о входящих вызовах через АТС (Asterisk).
* **Дни рождения (`NOTIF_BIRTHDAY`):** Вкл/Выкл общие уведомления о днях рождения коллег.
* Изменения происходят динамически: при клике на кнопку статус инвертируется (`0` ⇄ `1`), сохраняется в базу через стандартный `save()` и меню мгновенно перерисовывается с актуальными иконками (`🟢` / `🔴`).

### 3.5. Фоновые рассылки и уведомления (`BirthdayNotificationService`)
* Запускается по расписанию Cron (`0 30 9 * * *` — каждый день в 9:30 утра).
* **Алгоритм работы:**
    1. Ищет в корпоративном справочнике (`phonebook`) сотрудников, у которых сегодня день рождения.
    2. Делает рассылку персональных поздравлений самих именинников (если у них не отключены уведомления).
    3. Делает общую рассылку коллегам, **но строго фильтрует** получателей по условию `.filter { it.notifBirthday == 1 }`. Сотрудники, отключившие уведомления в настройках, рассылку не получают.
    4. В общие уведомления подтягиваются актуальные данные из справочника: ФИО, должность (📋) и отдел (🏢).

## 4. Схема жизненного цикла запроса (Пример: Нажатие кнопки настроек)

```text
[ Telegram / MAX Client ] 
       │ (Клик по кнопке инлайн-клавиатуры)
       ▼
[ MaxMainPollingService.pollUpdates() ]
       │ (Получение апдейта типа message_callback)
       ▼
[ handleAuthCallback(...) ] ──(Payload: "toggle_calls")
       │
       ├─► [ MaxUserAgnService.toggleCalls() ]
       │         │ (Поиск по chatId, инверсия флага, save() в Oracle)
       │         ▼
       │   [ Oracle DB (MAX_USER_AGN) ]
       │
       └─► Перерисовка меню настроек (вызов `settings`)
                 │
                 ▼
       [ MaxBotMainClientService ] ──► Отправка обновленного UI пользователю
