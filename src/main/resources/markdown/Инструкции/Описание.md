# 🚀 Инструкция по проекту, архитектуре и деплою (Oracle API)

## 📌 Общая информация
Проект представляет собой бэкенд-приложение на **Kotlin** и **Spring Boot** для работы с базой данных **Oracle**. API обслуживает мобильные терминалы сбора данных (ТСД), веб-клиенты и внешние интеграционные сервисы.

---

## 🏗️ Архитектурные правила и тесты (ArchUnit)
В проекте настроен расширенный набор автоматических архитектурных тестов (`ArchitectureTest.kt`), гарантирующих соблюдение стандартов чистого кода при каждой сборке:

1. **Слоистая архитектура (Layered Architecture):**
    * `Controller` изолирован и не имеет права напрямую обращаться к репозиториям.
    * `Service` содержит бизнес-логику и взаимодействует с `Repository`, `Config`, `Exception`.
    * `Repository` работает исключительно с базой данных и доступен только для сервисов и конфигураций.

2. **Строгое именование и суффиксы:**
    * `@RestController` классы обязательно заканчиваются на `Controller`.
    * `@Service` компоненты обязательно заканчиваются на `Service`.
    * Репозитории обязательно заканчиваются на `Repository`.
    * Конфигурационные классы (`@Configuration`) имеют суффикс `Config` или `Configuration`.
    * Классы в пакете `dto` используют утвержденные суффиксы (`Request`, `Response`, `Dto`, `Info`, `Status`, `Projection`, `Head`, `Spec`, `Details`).
    * Обработчики ошибок (`@ControllerAdvice`) находятся в пакете `exception` с суффиксом `Advice`.

3. **Безопасность и управление транзакциями:**
    * **Запрет транзакций в контроллерах:** Веб-слой не управляет сессиями БД.
    * **Транзакции чтения (`readOnly = true`):** Публичные сервисные методы считывания (`find`, `get`, `search`, `list` и др.) обязаны быть аннотированы `@Transactional(readOnly = true)` для оптимизации запросов к Oracle.
    * **Транзакции записи:** Методы модификации данных (`save`, `update`, `delete`, `create`, `execute` и др.) требуют обязательной аннотации `@Transactional`.

4. **Ограничения кодовой базы:**
    * **Изоляция API от Entity:** Контроллеры не возвращают и не принимают сущности БД напрямую (используются DTO).
    * **Запрет Field Injection:** Использование `@Autowired` на полях строго запрещено, применяется внедрение через конструктор (`Constructor Injection`).
    * **Потокобезопасность конфигураций:** Классы `@Configuration` обязаны содержать только неизменяемые (`final`) поля без плавающих состояний.
    * **Обязательный маппинг:** Каждый публичный метод контроллера должен иметь аннотацию маппинга (`@GetMapping`, `@PostMapping` и т.д.).

## 🛠️ Сборка и деплой через скрипт `push_image_ver.cmd`
Для локальной сборки, проверки тестов (включая ArchUnit и smoke-тест контекста `OracleApiApplicationTests`), упаковки в Docker и отправки в реестр используется скрипт **`push_image_ver.cmd`**.

### Порядок работы скрипта:
1. **Проверка окружения:** Проверяется доступность `docker` и `mvn`.
2. **Генерация версии:** Версия приложения формируется автоматически по количеству коммитов в Git (например, `1.25.142`), вычисляется динамический порт (`8000 + версия`) и имя контейнера.
3. **Генерация документации и сборка (`mvn dokka:dokka` + `mvn clean package`):**
    * Генерируется HTML-документация кода через **Dokka** и автоматически запекается в статику Spring Boot (`src/main/resources/static/docs`).
    * Запускается Maven-сборка с прогоном тестов. При обнаружении архитектурных нарушений (например, нарушение слоев или пропущенный `@Transactional`) сборка мгновенно прерывается (`BUILD FAILURE`).
4. **Docker:** Сборка образа, тегирование и отправка (`push`) в локальный реестр (`oracle-rest-api.ars:5001/oracle-api`).
5. **Очистка:** Удаление устаревших локальных образов через `docker image prune`.

## 🌐 Инфраструктура и управление (`oracle-rest-api.ars`)
Сервер **`oracle-rest-api.ars`** работает на базе **Ubuntu**:
* **Portainer GUI (порт `9000`):** визуальная панель управления контейнерами Docker.
* **Docker Registry (порт `5001`) и Registry UI (порт `7001`):** локальный репозиторий образов и веб-интерфейс контроля их версий.

### 🐳 Описание активных Docker-контейнеров
* **`oracle-dev`** (`8099:8080`) — тестовая среда для отладки новых фич.
* **`oracle-prod-166`** (`8166:8080`) — рабочий production-контейнер с пробросом трафика через Nginx.
* **`portainer`** (`9000:9000`) — панель управления Portainer CE.
* **`regime-app`** (порты `50063`, `5063`, `5995`) — вспомогательный микросервис обмена и маркировки (`lm-chz`).
* **`registry-registry-1`** (`5001:5000`) — локальный Docker Registry.
* **`registry-registry-ui-1`** (`7001:80`) — веб-интерфейс Registry UI.
* **`schemaspy-docs`** (`8070:8080`) — сервис генерации и хостинга документации схемы базы данных Oracle (**SchemaSpy**).
