# 🌿 Руководство по Git: Принципы работы и основные команды

Git — это распределенная система контроля версий, которая отслеживает изменения в исходном коде, позволяет безопасно работать в команде и легко откатываться к предыдущим стабильным версиям.

---

## 1. Главные принципы и зоны Git

### Три состояния файлов:
1. **Modified (Изменен):** Вы изменили файл в рабочей директории, но изменения еще не зафиксированы.
2. **Staged (Подготовлен):** Вы отметили измененный файл для включения в следующий коммит (`git add`).
3. **Committed (Зафиксирован):** Изменения надежно сохранены в локальной истории репозитория (`git commit`).

### Четыре основные зоны:
* **Working Directory (Рабочая папка):** Ваши файлы на компьютере, с которыми вы работаете.
* **Staging Area / Index (Зона индексации):** Промежуточный буфер, куда попадают файлы перед коммитом.
* **Local Repository (Локальный репозиторий):** База данных истории коммитов на вашем ПК (скрытая папка `.git`).
* **Remote Repository (Удаленный репозиторий):** Сервер (например, GitFlic или корпоративный сервер), где хранится общая версия проекта.

## 2. Базовый рабочий процесс (Daily Workflow)

### 📊 Проверка статуса файлов
Показывает измененные файлы, состояние индекса и текущую ветку:
```bash
git status
```

### ➕ Добавление файлов в индекс (Staging)
Добавить конкретный файл:
```bash
git add имя_файла
```
Добавить **все** измененные файлы сразу:
```bash
git add .
```

### 💾 Сохранение изменений (Коммит)
Зафиксировать подготовленные файлы в истории с понятным сообщением:
```bash
git commit -m "feat: добавлена обработка ошибок в GlobalErrorCounterAdvice"
```

### ☁️ Синхронизация с удаленным репозиторием
* **Скачать актуальные изменения с сервера и слить их (Pull):**
  ```bash
  git pull
  ```
* **Отправить свои локальные коммиты на сервер (Push):**
  ```bash
  git push
  ```

## 3. Работа с ветками (Branching)

Ветки позволяют разрабатывать новые фичи или исправлять баги изолированно, не ломая рабочий код в основной ветке (`main` или `master`).

* **Посмотреть список всех веток (активная отмечена звездочкой):**
  ```bash
  git branch
  ```
* **Создать новую ветку и сразу переключиться на нее:**
  ```bash
  git checkout -b feature/new-api
  # или современный аналог:
  git switch -c feature/new-api
  ```
* **Переключиться на существующую ветку:**
  ```bash
  git checkout main
  # или:
  git switch main
  ```
* **Влить изменения из другой ветки** (находясь в целевой ветке, например, `main`):
  ```bash
  git merge feature/new-api
  ```

---

## 4. История и полезные трюки

* **Посмотреть историю коммитов (компактный граф):**
  ```bash
  git log --oneline --graph --all
  ```
* **Посмотреть разницу в коде (что изменилось в файлах):**
  ```bash
  git diff
  ```
* **Временное сохранение изменений (Stash):**
  Полезно, если нужно срочно переключиться на другую ветку, а текущий код еще не готов для коммита:
  ```bash
  git stash
  ```
* **Вернуть спрятанные изменения обратно:**
  ```bash
  git stash pop
  ```
* **Отменить изменения в конкретном файле (вернуть к последнему коммиту):**
  ```bash
  git checkout -- имя_файла
  ```
