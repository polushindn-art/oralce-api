# Шаблон технического задания (ТЗ)

## Полная версия

```markdown
# ТЗ: [Название задачи]

**Дата:** ДД.ММ.ГГГГ  
**Версия:** 1.0  
**Автор:** [ФИО]  
**Ответственный:** [ФИО]

---

## 1. Общее описание
Кратко: что делаем, зачем, для кого.

## 2. Цель
Чего должны достигнуть.

## 3. Задача
Конкретные требования к реализации.

## 4. Место реализации
Где выполняется (модуль, ПО, устройство).

## 5. Архитектура / Состав
Компоненты системы и их взаимодействие.

## 6. Основные сущности
Объекты с полями.

## 7. Функциональные требования
Что система должна делать.

## 8. Нефункциональные требования
Производительность, безопасность, надёжность.

## 9. Алгоритм работы
Пошаговый процесс.

## 10. API / Эндпоинты
Методы, параметры, примеры.

## 11. Зависимости
От каких систем зависит.

## 12. Критерии приёмки
Чек-лист проверки.

## 13. Тестирование
Сценарии проверки.

## 14. Жизненные циклы
Состояния и переходы.

## 15. Обработка ошибок
Ошибки и их обработка.

## 16. Мониторинг и логирование
Что логируем, что мониторим.

## 17. Важные нюансы
Особенности, которые важно учесть.

## 18. Примеры
Запросы/ответы.

## 19. Диаграммы
Mermaid, UML.

## 20. Словарь терминов
Расшифровка сокращений.

## 21. Ссылки
На связанные документы.

## 22. Риски
Проблемы и решения.

## 23. Этапы реализации
План работ.

## 24. История изменений
Таблица версий.

## 25. Что сдаётся
Артефакты по итогу.

## 26. Ответственные
Кто делает, проверяет, утверждает.
```

```markdown
**Дата:** ДД.ММ.ГГГГ  
**Автор:** [ФИО]

---

## 2. Задача

## 3. Алгоритм работы
Пошагово как работает.

## 4. Критерии приёмки
Что проверяем.

## 5. Тестирование
Как проверяем.
```

# Памятка: когда какую версию ТЗ использовать

| Ситуация | Версия ТЗ |
|----------|-----------|
| Крупный проект, новая функциональность | Полная |
| Интеграция с несколькими системами | Полная |
| Новый API или сервис | Полная |
| Новая сущность / таблица в БД | Полная |
| Новая архитектура или модуль | Полная |
| Сложный бизнес-процесс | Полная |
| Исправление бага | Минимальная |
| Настройка параметров | Минимальная |
| Добавление маленького эндпоинта | Минимальная |
| Добавление одного поля в сущность | Минимальная |
| Тестовое задание | Минимальная |
| Доработка существующей функции | Минимальная |
