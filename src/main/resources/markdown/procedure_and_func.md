# Архитектура вызова хранимых процедур и функций

Ниже представлено описание компонентов (слоев) приложения для работы с хранимыми процедурами и функциями в базах данных (контекст Spring / JPA).

## Для процедур

*   **Controller**
    *   Отвечает за приём HTTP-запросов, валидацию входных данных и формирование ответа клиенту.
    *   Здесь определяются эндпоинты (например, `POST /api/mark/upd`).

*   **DTO (Data Transfer Object)**
    *   Объекты для передачи данных между клиентом и сервером. Содержат только поля, необходимые для конкретного запроса/ответа.
    *   Часто снабжаются аннотациями валидации (`@NotBlank`, `@NotNull`). Это позволяет изолировать внутреннюю модель от внешнего API.

*   **Entity (сущность)**
    *   В контексте процедур используется не столько для маппинга таблиц БД, сколько для описания самой процедуры с помощью `@NamedStoredProcedureQuery`.
    *   В этой сущности указывается имя процедуры, её параметры и режимы (`IN`/`OUT`). Хотя сущность должна быть JPA-сущностью (с `@Entity` и `@Id`), она может быть пустой и служить только контейнером для метаданных процедуры.
    *   *Альтернатива:* можно обойтись без отдельной сущности и вызывать процедуру напрямую через `EntityManager`, но описание через `@NamedStoredProcedureQuery` удобно для повторного использования.

*   **Service**
    *   Содержит бизнес-логику: преобразование DTO в параметры процедуры, вызов процедуры через репозиторий или `EntityManager`, обработку результатов и исключений, замер времени выполнения.
    *   Сервис скрывает детали работы с БД от контроллера.

---

## Для функций

*   **Controller**
    *   Остаётся без изменений: принимает запрос, валидирует DTO, вызывает сервис, возвращает ответ.

*   **DTO**
    *   Также необходимы: один для запроса (входные параметры) и один для ответа (результат выполнения функции).

*   **Service**
    *   Содержит логику вызова функции. Здесь рекомендуется использовать `EntityManager.createNativeQuery()` с SQL-запросом вида `SELECT your_function(:param) FROM DUAL` (для Oracle) или аналогичным для других БД. Это самый простой и надёжный способ.

*   **Entity (для описания функции) — НЕ требуется**
    *   В отличие от процедур, для функций не нужно создавать JPA-сущность с `@NamedStoredProcedureQuery`, так как этот механизм не поддерживает функции с возвращаемым значением (`RETURN`). Поэтому можно обойтись без отдельной сущности, ограничившись сервисом.

---

### Ключевые различия

| Компонент | Процедуры | Функции |
| :--- | :--- | :--- |
| **Entity** | Используется для `@NamedStoredProcedureQuery` | Не требуется |
| **Способ вызова** | Через `@Procedure` в репозитории или `EntityManager` | Через `EntityManager.createNativeQuery()` с SQL-функцией |
| **Тип результата** | `OUT` параметры или результат как множеств | Возвращаемое значение `RETURN` |
