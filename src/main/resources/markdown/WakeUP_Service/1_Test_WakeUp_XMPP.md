# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
## WakeUpTest (Тестовый сервис пробуждения для Android)

**Версия:** 0.1 (Тестовая)  
**Цель:** Проверка возможности создания сервиса пробуждения и оценка его влияния на энергопотребление

**Авторы:**
- Полушин Д.Н. — программист

---

## 1. Цель работы

Создать тестовый сервис пробуждения для Android, который позволит ответить на вопросы:

| Вопрос                                     | Как проверяем                                                                                               |
|--------------------------------------------|-------------------------------------------------------------------------------------------------------------|
| Может ли сервис постоянно работать в фоне  | Запускаем сервис, выключаем экран, оставляем на **весь рабочий день** (09:00-17:00), периодически проверяем |
| Помогает ли исключение из энергосбережения | Сравниваем: работает ли сервис всю ночь (15 часов) с исключением и без него                                 |
| Как влияет сервис на расход батареи        | Измеряем расход за ночь (15 часов) с работающим сервисом и без него                                         |
| Как ведут себя разные устройства           | Тестируем на ТСД и смартфонах                                                                               |

> Важно: Это тестовая версия. Логин/пароль для подключения к OpenFire задаются в коде вручную.

## 2. Что делает сервис

| Функция                | Описание                                                                 |
|------------------------|--------------------------------------------------------------------------|
| Постоянная работа      | Сервис висит в шторке и не выгружается                                   |
| Подключение к Openfire | Подключается к тестовому XMPP серверу                                    |
| Получение сообщения    | Ждёт одно тестовое сообщение                                             |
| Показ Toast + звук     | При получении сообщения показывает Toast и воспроизводит звуковой сигнал |
| Автозапуск             | При перезагрузке запускается сам                                         |

## 4. Настройка (делает администратор один раз)

### 4.1. Когда открывается Activity

Activity (экран настройки) открывается **только в следующих случаях**:

| Ситуация | Что происходит |
|----------|----------------|
| **Первый запуск после установки** | Открывается экран настройки (так как исключение ещё не добавлено) |
| **Приложение не добавлено в исключения** | Открывается экран настройки |
| **Сервис не может запуститься из-за ограничений** | Открывается экран настройки |
| **Всё настроено правильно** | Activity **НЕ открывается**, сервис запускается сразу в фоне |

### 4.2. Как проверить, нужно ли открывать Activity

При каждом запуске приложение проверяет:

| Проверка | Если НЕ пройдена |
|----------|------------------|
| Приложение добавлено в исключения энергосбережения | → открыть Activity |
| Разрешён автозапуск (для китайских устройств) | → открыть Activity |
| Разрешена фоновая активность | → открыть Activity |

**Если все проверки пройдены → Activity не показывается, сервис запускается молча.**

### 4.3. Содержимое Activity

| Элемент | Описание |
|---------|----------|
| Текст | "Для работы сервиса необходимо отключить оптимизацию батареи" |
| Кнопка | "Открыть настройки" (открывает системные настройки батареи для этого приложения) |
| Кнопка | "Проверить снова" (перепроверяет статус и закрывает Activity, если всё настроено) |

### 4.4. Повторное открытие Activity

Если администратор закрыл Activity, но настройки так и не сделал — при следующем запуске приложения Activity откроется снова, пока настройки не будут выполнены.

### 4.5. Завершение настройки

После того как администратор:
1. Добавил приложение в исключения
2. Вернулся в приложение
3. Нажал "Проверить снова"

→ Activity закрывается, сервис запускается.

**В дальнейшем Activity больше не показывается (пока настройки не собьются, например, после обновления прошивки).**

**Важно:** На разных устройствах и версиях Android названия пунктов и расположение могут отличаться. Администратор должен убедиться, что приложение Wake Up Test добавлено во все исключения энергосбережения и автозапуска, доступные на данном устройстве.

**Общий принцип:** Приложение не должно быть ничем ограничено — ни батареей, ни автозапуском, ни фоновой активностью.

## 6. Тестирование

### 6.1. Функциональные тесты

| № | Что делаем                     | Ожидаем                        |
|---|--------------------------------|--------------------------------|
| 1 | Устанавливаем и запускаем      | В шторке появилось уведомление |
| 2 | Добавляем в исключения батареи | Сервис работает                |
| 3 | Отправляем одно XMPP сообщение | Появился Toast + звук          |
| 4 | Перезагружаем устройство       | Сервис запустился сам          |
| 5 | Выключаем экран на 1 час       | Сервис жив, сообщение проходит |

### 6.2. Тесты энергопотребления

**Условия проведения:**
- Устройство отключено от зарядки
- Экран выключен
- Wi-Fi включён
- Длительность: **15 часов (с 18:00 до 09:00)**

| № | Сценарий | Длительность | Что измеряем |
|---|----------|--------------|--------------|
| 1 | Экран выключен, сервис **остановлен** | 15 часов (с 18:00 до 09:00) | Базовый расход |
| 2 | Экран выключен, сервис **работает** | 15 часов (с 18:00 до 09:00) | Расход с сервисом |
| 3 | Экран выключен, сервис работает, 10 сообщений в час | 15 часов (с 18:00 до 09:00) | Расход при нагрузке |

**Почему 15 часов (ночь):**
- Устройство не используется, экран выключен
- Идеальные условия для замера влияния на батарею
- Отсутствие человеческого фактора

### 10.3. Тест с нагрузкой (автоматическая отправка сообщений)

Для теста "Нагрузка (10 сообщений в час)" необходим дополнительный скрипт или утилита, которая будет автоматически отправлять XMPP сообщения на тестового пользователя с заданным интервалом.

| Параметр | Значение |
|----------|----------|
| Интервал отправки | 1 сообщение каждые 6 минут |
| Всего сообщений за ночь | 150 сообщений (10 сообщений/час × 15 часов) |
| Способ отправки | XMPP клиент (скрипт на Python/Java или утилита sendxmpp) |
| Получатель | Логин тестового ТСД (test_user_1) |

**Требования к скрипту:**
- Поддержка XMPP протокола
- Возможность указать логин/пароль отправителя
- Возможность указать получателя
- Отправка сообщений по таймеру (каждые N минут)
- Логирование факта отправки (время, успех/ошибка)

## 11. Что сдаётся по итогу теста

1. **Исходный код** тестового сервиса
2. **APK файл** для установки
3. **Протокол тестирования**

**Проверка:** После настройки принудительно перезагрузить устройство и убедиться, что сервис запустился автоматически и уведомление в шторке появилось.
