# План реализации WakeUp Service

## Общая длительность: 3-5 недель

---

## Этап 1: WakeUpTest (XMPP + Toast + звук) — 4-5 дней

### Что делаем

1. Создаём Android проект, добавляем Smack
2. Делаем Foreground Service с уведомлением в шторке
3. Настраиваем автозапуск при перезагрузке
4. Подключаемся к Openfire (хост, порт, логин, пароль — из кода)
5. Вешаем слушатель на входящие XMPP сообщения
6. При получении — показываем Toast и проигрываем звук
7. Делаем Activity настройки: кнопка "Открыть настройки батареи", проверка исключений
8. Логируем всё в файл

### Возможные проблемы

| Проблема                                 | Признак                                | Решение                                                                                |
|------------------------------------------|----------------------------------------|----------------------------------------------------------------------------------------|
| Openfire недоступен                      | Не коннектится, таймаут                | Договориться с админом заранее, проверить `telnet`                                     |
| Нет учётной записи test_user_1           | Ошибка авторизации                     | Создать в Openfire Admin                                                               |
| Сервис убивается после выключения экрана | Уведомление пропало                    | Добавить `startForeground()` с ongoing=true                                            |
| Автозапуск не работает на китайских ТСД  | После перезагрузки сервис не стартовал | Добавить `QUICKBOOT_POWERON`, дать инструкцию по настройке автозапуска в меню телефона |
| Не пишутся логи на Android 11+           | Permission denied                      | Использовать `getExternalFilesDir()` вместо `/sdcard/`                                 |
| Toast не показывается из сервиса         | Тишина                                 | Использовать `Handler` с `Looper.getMainLooper()`                                      |
| Звук не играет                           | Молчит                                 | Проверить MediaPlayer, добавить стандартный звук уведомления                           |

## Этап 2: WakeUpTest-HTTP (XMPP + HTTP пинг) — 4-5 дней

### Что делаем

1. Добавляем OkHttp с таймаутами 3 секунды
2. При получении XMPP сообщения отправляем POST `/wakeup/ping` с deviceId
3. Добавляем WakeLock на время HTTP запроса
4. Реализуем GET `/wakeup/info` для проверки счётчика
5. Обрабатываем ошибки: таймауты, недоступность сервера (логируем, не падаем)
6. Тестируем на порту 3001 (нестабильный режим)
7. Пишем простой Python скрипт для отправки 10 сообщений/час

### Возможные проблемы

| Проблема | Признак | Решение |
|----------|---------|---------|
| REST API недоступен | Таймаут, ошибка соединения | Логируем, сервис продолжает работу |
| HTTP запрос блокирует XMPP | Сообщения обрабатываются медленно | Сделать запрос асинхронным (OkHttp.enqueue) |
| Счётчик не увеличивается | GET /info показывает 0 | Проверить параметр device, формат JSON |
| Порт 3001 ведёт себя непредсказуемо | Иногда 500, иногда таймаут | Проверить, что сервис не падает и продолжает ждать новые сообщения |
| WakeLock не отпускается | Батарея быстро садится | Установить timeout 5 секунд, отпускать в finally |
| Скрипт отправки не работает | Нет сообщений на ТСД | Проверить логин отправителя, JID получателя |
| Wi-Fi отключается при выключении экрана | Пинги не проходят, сообщения не доходят | Настроить Wi-Fi Sleep Policy на устройстве |

## Этап 3: Финальная версия — 8-12 дней

### Что делаем

1. Рефакторим код: XMPPManager, HTTPManager, WakeLockManager
2. Вместо жёстких учётных данных — запрашиваем их у REST API: GET `/v1/auth/xmpp?deviceId=...`
3. Реализуем повторы при ошибке: 5 раз с интервалом 10 секунд
4. Безопасность: пароль не логируем, храним только в памяти
5. При получении XMPP сообщения отправляем POST `/v1/wakeup/confirm`
6. Будим WMS приложение:
    - Сначала пробуем Broadcast (`com.wms.WAKEUP`)
    - Если нет ответа — Intent с `FLAG_ACTIVITY_NEW_TASK`
7. WMS само загружает задания через GET `/v1/tasks` и сортирует по priority
8. Полное тестирование на 4 устройствах, ночные замеры расхода

### Возможные проблемы

| Проблема | Признак | Решение |
|----------|---------|---------|
| GET /v1/auth/xmpp не работает | 404, 400, 401 | Проверить реальный эндпоинт, скорректировать код |
| Учётные данные изменились, а сервис использует старые | Ошибка авторизации XMPP | При ошибке авторизации — запросить новые данные |
| Пароль попадает в лог | Виден в logcat или файле | Убрать логирование пароля, замаскировать |
| WMS не реагирует на Broadcast | Тишина | Использовать Intent как fallback |
| WMS не реагирует ни на что | Не запускается | Проверить package name, проверить, что WMS установлен |
| WMS запускается, но не открывает задание | Открыт главный экран | WMS сам должен вызвать GET /tasks, это не задача WakeUp |
| Сервис падает после получения сообщения | Краш, лог ошибки | Проверить, что все операции асинхронные, нет NetworkOnMainThread |
| На китайском ТСД сервис всё равно убивают | Уведомление пропадает через N часов | Искать меню "Защита приложений", "Запуск при фоновой работе", "Автозапуск" — у каждого производителя своё |
| Расход батареи выше +10% | За ночь упало 30% вместо 20% | Проверить WakeLock — не забыли отпустить, проверить интервалы XMPP ping |

## Что проверяем на каждом устройстве перед запуском тестов

1. Сервис запустился — есть уведомление в шторке
2. XMPP подключился — есть запись в логе
3. Можем отправить тестовое сообщение — Toast + звук
4. Перезагружаем — сервис стартовал сам
5. Выключаем экран на 1 час — сервис жив, сообщение проходит

---

## Признаки, что всё пошло не так (и что делать)

| Ситуация | Действие |
|----------|----------|
| Openfire не отвечает на День 0 | Не начинаем разработку, пока не починят |
| Сервис падает при первом запуске | Смотрим logcat, исправляем критическую ошибку |
| На ТСД сервис умирает через час | Ищем меню энергосбережения производителя, добавляем в исключения |
| WMS не запускается после 10 попыток | Проверяем package name, логи WMS |
| REST API отвечает не по ТЗ | Просим документацию, подстраиваем код под реальность |
| Батарея садится на 20% за ночь | Ищем лишние WakeLock, уменьшаем XMPP ping интервал |

## Буфер на проблемы (что может занять время)

| Ситуация | Сколько времени закладывать |
|----------|----------------------------|
| Убивание сервиса на ТСД | 2-3 дня на поиск всех меню |
| REST API делают параллельно и он запаздывает | 2-4 дня ожидания |
| Openfire требует настройки со стороны админа | 1-2 дня |
| WMS приложение не готово к интеграции | 1-3 дня |
| Нестабильный Wi-Fi на складе | 1 день на диагностику |
